# 统一维护后台设计

## 目标

在统一入口中新增一个总后台，让模板、变量、机构主数据、模板版本和发布校验都可以在 Web 端维护。维护人员不需要修改 Python、PowerShell 或前端源码，就能完成日常模板调整、变量新增、机构信息更新和模板回退。

## 设计原则

- 统一入口是管理面，两个子系统是运行面。
- 配置文件是唯一真相来源，源码只负责读取、校验和渲染。
- 保存和发布分离，避免误改立即影响生成结果。
- 每次保存前自动备份，发布前必须校验。
- 第一阶段使用 JSON 文件，不引入数据库和迁移复杂度。

## 总体架构

统一入口新增 `/admin` 后台。后台读写统一入口下的 `config/` 和 `managed_assets/`，并将发布后的配置同步给 ETF 与 ETF联接两个子系统。

核心数据文件：

- `config/template_manifest.json`：模板资产清单。
- `config/variable_registry.json`：变量注册表。
- `config/organization_master_data.json`：机构主数据。
- `config/publish_state.json`：当前发布状态、校验结果和发布时间。

核心资产目录：

- `managed_assets/templates/etf/`
- `managed_assets/templates/linked/`
- `backups/maintenance-admin/`

## 后台模块

### 模板资产

管理 `.md`、`.json`、`.docx` 模板。每个模板记录逻辑名称、系统、用途、当前文件、版本号、必需占位符、备注和更新时间。

支持动作：

- 上传新文件。
- 设置当前版本。
- 查看历史版本。
- 回退到旧版本。
- 运行单模板校验。

### 变量注册表

管理变量名、中文标签、类型、默认值、是否必填、适用系统、适用模板、示例、说明和来源。

变量名必须唯一。新增变量后，模板编辑器可以直接搜索和插入，减少手工拼错。

### 机构主数据

管理基金管理人、托管人、会计师事务所、律师事务所等信息。

第一阶段字段以现有生成逻辑为基础：

- 管理人：名称、住所、法定代表人、设立日期、注册资本、官网、客服电话、简介版本。
- 托管人：名称、住所、办公地址、法定代表人、成立日期、注册资本、托管资格批文、托管类型、划款方式。
- 会计师事务所：名称、住所、办公地址、经办注册会计师、简介。
- 律师事务所：名称、住所、经办律师、简介。

### 模板编辑器

Web 端编辑正文模板。布局采用工作台样式：

- 左侧文件列表。
- 中间编辑区域。
- 右侧变量和机构字段面板。
- 底部校验结果。

支持保存草稿、发布当前版本、插入变量、搜索变量和查看未注册变量。

### 校验与发布

发布前运行校验：

- manifest 指向的文件存在。
- DOCX 可以打开。
- 模板中的变量都已注册。
- 必填变量有默认值、机构来源或表单来源。
- 打包脚本可以从 manifest 找到所有发布资产。
- 生成结果不残留 `{{...}}` 占位符。

校验失败时禁止发布，保存草稿不受影响。

## 子系统兼容策略

第一阶段保留旧路径和旧文件名兼容。子系统优先读取统一入口发布出的配置；如果配置不存在，则回退到现有本地文件。

这能保证后台上线失败时，原有系统仍能按旧方式运行。

## 备份和回退

实施前创建一次项目级备份：

- 统一入口关键源码和模板。
- ETF 子系统关键模板、配置和 packaged assets。
- ETF联接子系统关键模板、配置和 packaged assets。

后台运行后，每次保存会在 `backups/maintenance-admin/YYYYMMDD-HHMMSS/` 生成文件级备份。发布版本可以按 manifest 回退。

## UI 风格

后台是内部工作台，不做营销页。

- 左侧固定导航：模板资产、变量注册表、机构主数据、模板编辑器、校验记录。
- 顶部系统筛选：全部、ETF、ETF联接。
- 表格为主，右侧抽屉编辑。
- 保存草稿和发布生效分开。
- 回退、发布、覆盖模板等危险操作二次确认。
- 校验结果用红、黄、绿状态，并能定位到模板和变量。

## 分阶段实施

第一阶段：

- 建立配置文件和资产目录。
- 新增后台页面。
- 支持模板资产、变量、机构数据编辑。
- 支持保存备份、发布校验。
- 打包脚本读取 manifest。
- 子系统读取统一配置并保留旧路径回退。

第二阶段：

- 增强 DOCX 在线预览和差异对比。
- 模板编辑器变量自动补全。
- 从 Excel 批量导入机构主数据。
- 生成样例回归测试。

第三阶段：

- 操作日志、权限控制和审批流。
- SQLite 或其他持久层迁移。
