# 基金合同要素录入表（UI设计规范）

**用途：** 开发人员构建基金合同自动生成系统时参考的字段规范，定义界面字段顺序、输入类型、联动规则等。

## 第一组：基金基本信息

| # | 字段名（中文） | 变量名 | 输入类型 | 是否必填 | 默认值/选项 | 填写说明 |
|---|-------------|-------|---------|---------|-----------|---------|
| 1 | 基金全名 | FUND_NAME | 文本框（长）| ✓ | 按指数名称自动生成，可手动覆盖 | 格式：南方XXXX交易型开放式指数证券投资基金 |
| 2 | 基金简称 | FUND_SHORT_NAME | 文本框（中）| ✓ | 按指数名称自动生成，可手动覆盖 | 如：南方创业板中盘200ETF |
| 3 | 基金代码 | FUND_CODE | 文本框（短，6位数字）| 否 | 无 | 上市后确认，募集前可留空 |
| 4 | 标的指数名称 | INDEX_NAME | 文本框（中）| ✓ | 无 | 如：创业板中盘200指数 |
| 5 | 标的指数代码 | INDEX_CODE | 文本框（短）| ✓ | 无 | 如：399371（创业板）/ 000688（科创50） |
| 6 | 指数编制机构 | INDEX_COMPILER | 文本框（中）| 否 | 自动推断，可手动覆盖 | 如：深圳证券信息有限公司 / 中证指数有限公司 |
| 7 | 合同签署日期 | CONTRACT_DATE | 月份选择器 | ✓ | 当月 | 格式：XXXX年X月 |

### 指数信息自动联动规则

- `INDEX_NAME` 含 `中证` / `上证` / `科创板` 时：自动回填 `INDEX_COMPILER = 中证指数有限公司`、`INDEX_WEBSITE = https://www.csindex.com.cn`
- `INDEX_NAME` 含 `创业板` / `深证` / `国证` 时：自动回填 `INDEX_COMPILER = 深圳证券信息有限公司`、`INDEX_WEBSITE = http://www.cnindex.com.cn`
- `INDEX_NAME` 含 `恒生` 时：当前按 `深圳证券信息有限公司` / `http://www.cnindex.com.cn` 规则回填
- 自动生成基金名称：`FUND_NAME = 南方 + INDEX_NAME（去掉“指数”） + 交易型开放式指数证券投资基金`
- 自动生成基金简称：`FUND_SHORT_NAME = 南方 + INDEX_NAME（去掉“指数”） + ETF`
- 指数简介变量：`INDEX_DESCRIPTION`，用于招募说明书“重要提示”中的指数简介段落，当前在前端界面中为必填项
- 指数公司官网变量：`INDEX_WEBSITE`
- 前端仅在字段为空或仍等于上一次自动值时覆盖，手工改写后的值保留

**⚠️ 此组字段存在联动规则，会自动填充多个下游字段**

| # | 字段名（中文） | 变量名 | 输入类型 | 是否必填 | 选项 | 填写说明 |

| 9 | 投资市场类型 | MARKET_TYPE | 下拉框 | ✓ | 普通A股 (A_SHARE) / 创业板 (CHUANGYE) / 科创板 (KECHUANG) / 港股通 (HK_CONNECT) | **联动触发项** |
| 10 | 工作日定义类型 | WORKING_DAY_TYPE | 下拉框 | ✓ | 仅深交所 / 仅上交所 / 沪深两所 | **通常自动推导，可手动调整** |
| 11 | 《业务规则》类型 | BUSINESS_RULES_TYPE | 下拉框 | ✓ | 深交所版 (SZSE) / 上交所版 (SSE) | **通常自动推导** |
| 11A | 争议解决地点 | DISPUTE_RESOLUTION_VENUE | 下拉框 | ✓ | 深圳-深圳国际仲裁院 (SZ_SCIA) / 北京-中国国际经济贸易仲裁委员会 (BJ_CIETAC) | 默认深圳口径，可按产品文本选择北京口径 |

### 联动规则说明

```
当 EXCHANGE = 深交所 (SZSE) 时：
  → WORKING_DAY_TYPE  = SZSE_ONLY（可调整）
  → BUSINESS_RULES_TYPE = SZSE（自动）
  → EXCHANGE_NAME_CN = "深圳证券交易所"（自动）

当 EXCHANGE = 上交所 (SSE) 时：
  → WORKING_DAY_TYPE  = SSE_ONLY（可调整）
  → BUSINESS_RULES_TYPE = SSE（自动）
  → EXCHANGE_NAME_CN = "上海证券交易所"（自动）

当 MARKET_TYPE = 港股通 (HK_CONNECT) 时：
  → HAS_HK_CONNECT    = true（自动）
  → TRACKING_ERROR_DAILY  = 0.35（默认，可调整）
  → TRACKING_ERROR_ANNUAL = 4（默认，可调整）
  → HAS_STOCK_SUBSCRIPTION = false（默认，通常不变）

当 MARKET_TYPE = 普通A股 / 创业板 / 科创板 时：
  → HAS_HK_CONNECT    = false（自动）
  → TRACKING_ERROR_DAILY  = 0.2（默认，可调整）
  → TRACKING_ERROR_ANNUAL = 2（默认，可调整）
  → NON_COMPONENT_SCOPE = 自动填充对应文本（可查看预览）

当 EXCHANGE = 深交所 且 MARKET_TYPE ≠ 港股通 时：
  → HAS_STOCK_SUBSCRIPTION = 优先提示true，但需按产品实际开通情况确认

当 EXCHANGE = 上交所 且 MARKET_TYPE = 科创板 时：
  → HAS_STOCK_SUBSCRIPTION = 优先提示true（按当前上交所科创板ETF样本）

争议解决地点：
  → DISPUTE_RESOLUTION_VENUE = SZ_SCIA 时，基金合同争议提交深圳国际仲裁院，仲裁地点为深圳市
  → DISPUTE_RESOLUTION_VENUE = BJ_CIETAC 时，基金合同争议提交中国国际经济贸易仲裁委员会，仲裁地点为北京市
  → 该字段同步影响基金合同正文、基金合同内容摘要和基金产品资料概要重要提示
```

### 管理费和托管费支付方式

- 来源口径：以对应基金招募说明书“基金的费用与税收”章节为准，不使用官方托管人名录直接推断。
- 默认规则：有明确披露才回填；未找到披露时，`MGMT_FEE_PAYMENT_METHOD` 与 `CUSTODY_FEE_PAYMENT_METHOD` 保持空值并提示人工补录。
- 字段关系：两个字段允许独立维护，系统优先按托管人已补录的历史产品原文回填，不再强制映射到固定枚举值。

### 分步表单推荐结构

1. **步骤一：基本信息**（字段1-7）

### 差异条款实时预览建议

在编辑表单时，右侧面板应实时显示受影响条款的原文预览，特别是：
- 第二部分释义第39条（工作日）
- 第二部分释义第44条（业务规则）
- 第十四部分第三条（跟踪误差）
- 第十七部分第二条（费用划款）
- 第十八部分第三条第2款（收益分配频率）

## 港股通补充说明（2026-04）

- `BUSINESS_RULES_TYPE` 已补充 `CSDC` 取值，用于 `EXCHANGE=SZSE` 且 `MARKET_TYPE=HK_CONNECT` 的深市港股通 ETF。
- 港股通逻辑拆成两层：`HAS_HK_CONNECT` 负责所有港股通共性条款，系统内部再按 `EXCHANGE + MARKET_TYPE=HK_CONNECT` 派生 `SSE_HK` / `SZSE_HK`。
- `DISTRIBUTION_FREQ` 与港股通无关，继续单独控制收益分配条款，不参与港股通子场景推导。
- `MGMT_FEE_PAYMENT_METHOD` / `CUSTODY_FEE_PAYMENT_METHOD` 继续按托管人口径或原文覆盖，不因港股通自动切换。
